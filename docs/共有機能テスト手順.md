# ブレイン共有機能 受け入れテスト手順

対象: 要件定義書 §8.2 #5「共有:同僚に共有し、相手が会話できる」
前提: 本番 DB に 0027(共有)適用済み ✅ / ハイブリッド検索を含む最新版がデプロイ済み

---

## 0. 前提の確認(まずこれ)

共有パネルは **「組織(エンタープライズ)に所属したアカウント」でのみ表示**されます。個人アカウントには出ません。
Supabase の SQL Editor で以下を実行し、テストできる状態かを確認してください。**読み取りのみ**です。

```sql
-- 組織とそのメンバーの一覧
select
  o.name                as 組織名,
  o.seats               as 契約シート数,
  count(u.email)        as 所属人数,
  string_agg(u.email || case when u.org_role = 'company_admin'
                             then '(会社管理者)' else '' end, ', ') as メンバー
from organizations o
left join app_users u on u.org_id = o.id
group by o.id, o.name, o.seats
order by o.name;
```

**判定**

| 結果 | 次にすること |
|---|---|
| 組織があり、**同じ組織に2名以上** | そのまま STEP 1 へ |
| 組織はあるが**1名だけ** | STEP 0-A でメンバーを追加 |
| **組織が無い** | STEP 0-B で組織を作成 |

### STEP 0-A: 同じ組織にメンバーを追加する

画面から実施できます(SQL 不要)。

1. **会社管理者**でログイン → マイページ → **「メンバー管理(自社)」**
2. 「メンバーを招待」からテスト用のメールアドレスと初期パスワードを設定
3. シート数が足りない場合は、運営者アカウントで 管理者 →「組織・シート管理」からシート数を増やす

### STEP 0-B: 組織を作成する

運営者(`role='admin'`)でログイン → マイページ → **「組織・シート管理」**

1. 組織を作成(会社名・シート数を 2 以上に設定)
2. 同じ画面で会社管理者を作成し、その組織に割り当てる
3. 続けて STEP 0-A でもう1名追加する

## 1. 共有する側の確認(所有者)

**組織に所属したアカウント A** でログインします。

| # | 操作 | 期待する結果 |
|---|---|---|
| 1-1 | ブレインを1つ開く | 詳細画面が表示される |
| 1-2 | 画面上部を確認 | **「社員に共有」パネルが表示されている**(個人アカウントでは出ない) |
| 1-3 | パネルを開く | 自社メンバーの一覧が出る。**自分自身は候補に出ない** |
| 1-4 | アカウント B を選んで「共有設定を保存」 | 「保存しました」と表示される |
| 1-5 | パネルの見出しを確認 | 「◯人」バッジが出る |

**「会社全体に共有」でも確認**: チェックを入れて保存すると、バッジが「会社全体」に変わること。

---

## 2. 共有された側の確認(最重要)

**アカウント B** でログインします(別ブラウザまたはシークレットウィンドウ推奨)。

| # | 確認項目 | 期待する結果 |
|---|---|---|
| 2-1 | ダッシュボード | 共有されたブレインが**「共有」バッジ付き**で並ぶ。「◯◯ から共有」と表示される |
| 2-2 | そのブレインを開く | 名前の横に**「共有」バッジ**。右側に**「閲覧・会話のみ」**の説明カード |
| 2-3 | **会話できるか** | 音声・テキストとも**通常どおり応答する**(これが本機能の目的) |
| 2-4 | **学習パネル** | **表示されない**(「学習させる」タブが無い) |
| 2-5 | **詳細設定** | **表示されない**(声・言語・回答ルールを変更できない) |
| 2-6 | **名前・説明** | クリックしても**編集できない**(静的表示) |
| 2-7 | **写真の変更ボタン** | アイコン・背景とも**表示されない** |
| 2-8 | **共有パネル** | **表示されない**(共有相手は再共有できない) |
| 2-9 | ダッシュボードのカード | 共有ブレインに**ゴミ箱メニューが出ない**(削除できない) |

---

## 3. 権限の確認(重要)

| # | 操作 | 期待する結果 |
|---|---|---|
| 3-1 | アカウント B で `/avatars/[共有されたブレインID]/training` を直接開く | **エラーになる**(素材管理は所有者専用) |
| 3-2 | アカウント A が共有を解除(チェックを外して保存) | アカウント B のダッシュボードから**消える**(再読込後) |
| 3-3 | アカウント A がブレインをゴミ箱へ移動 | アカウント B から**アクセスできなくなる** |

> 認可そのものは自動テスト18件で検証済みです(`authServer.security.test.ts`)。ここでは**画面の見え方**が意図どおりかを確認します。

---

## 4. 別組織から見えないことの確認(任意)

別の組織のアカウント C があれば、そのアカウントで**共有ブレインが一覧に出ないこと**を確認してください。
アカウントが無い場合は、自動テストで検証済みのため省略して構いません。

## 結果の記録

すべて期待どおりなら、要件定義書 §8.2 #5 を **✅ 完了**に更新します。

**特に報告してほしいケース**

- 2-3 で**会話できない** → 共有の中核機能が動いていないため最優先で調査します
- 2-4〜2-8 で**編集 UI が出てしまう** → 権限漏れの可能性。該当画面と操作を教えてください
- 1-2 で**共有パネルが出ない** → アカウントが組織に所属していない可能性。STEP 0 の SQL 結果を教えてください
